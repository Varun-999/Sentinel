## 5.1 Test Levels

### 5.1.1 Unit Testing

*Scope*: Individual Python functions in the **Red**, **Blue**, and **Green** agents as well as the sandbox `TestHarness` utilities.

*Approach*:
- **PyTest** is used for deterministic function‑level verification.
- Each agent method (`RedAgent.run_payloads`, `BlueAgent.synthesize_patch`, `GreenAgent.verify_patch`) is exercised with a minimal synthetic payload and a mock `RemediationState`.
- Mock objects replace the external LLM API (`LLMService`) and Flask subprocess to guarantee repeatable outcomes.

*Coverage*: > 95 % line coverage across `sentinel_code/backend/app/services/llm.py`, `test_harness.py`, and the LangGraph workflow definition.

---

### 5.1.2 Integration Testing

*Scope*: Interaction between agents and the shared `RemediationState` model.

*Approach*:
- A **pytest‑fixture** constructs a full workflow graph (`workflow_app`) and runs it against a single synthetic vulnerability (e.g., SQL Injection).
- The test asserts that after the graph finishes, the state contains:
  - `vulnerability_checklist["SQL"] == True`
  - `patch_diff` is non‑empty and syntactically valid Python.
  - `verification_status == "PASS"`.

*Outcome*: Guarantees that the LangGraph orchestration correctly propagates state between agents.

---

### 5.1.3 Black‑Box (Adversarial) Testing

*Scope*: The **Red Agent** performs dynamic exploitation against a live sandbox server without any knowledge of the underlying source code.

*Approach*: Mirrors a classic penetration‑testing methodology:
1. Deploy the vulnerable sample via `TestHarness`.
2. Sequentially inject each payload from the **13‑class payload library**.
3. Record any observable exploit signal (e.g., leaked flag, HTML injection, OS command output).

*Result Metric*: **Exploit Confirmation Ratio** – the proportion of payloads that produce a concrete, detectable effect. This metric feeds directly into the `vulnerability_checklist`.

---

### 5.1.4 System‑Level End‑to‑End Testing

*Scope*: Full batch execution of the **Sentinel** pipeline across the synthetic dataset generated by `dataset_extractor.py`.

*Approach*:
- Run `batch_runner.py` which iterates over the manifest of 20 test cases.
- Capture per‑case logs (`batch_<CVE>.json`) and the aggregate `batch_report.json`.
- Validate the **global metrics** (TPR, Patch Success Rate, MTTR, Regression Rate) against the expected thresholds defined in the project requirements.

*Automation*: The entire batch is executed as a CI job (GitHub Actions) to guarantee reproducibility on every commit.
